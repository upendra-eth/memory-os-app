================================================================================
                        DAILY REMINDER SYSTEM (NEW)
================================================================================

WHAT IT DOES
  • Sends sticky notification at 9 AM (configurable)
  • Reminds users to log their daily entry
  • Direct link to entry creation page
  • One-click dismiss (snoozes until next day)
  • Auto-resets at midnight

HOW IT WORKS
  • Zustand store for state management
  • js-cookie for persistent storage
  • Client-side timing (no server needed)
  • Tracks dismissal dates
  • Per-user configuration

WHEN IT SHOWS
  ✅ Once per day (9 AM by default)
  ✅ Only if enabled
  ✅ Only if not dismissed today
  ✅ After user completes onboarding

USER FLOW
  1. Complete onboarding → Reminder initialized
  2. Next day at 9 AM → Notification appears
  3. Option A: Click "Add Entry" → Go to /add
  4. Option B: Click "X" → Dismiss until tomorrow

CODE LOCATIONS
  Store: lib/notification-store.ts (Zustand + utilities)
  UI: components/daily-reminder.tsx (notification component)
  Wrapper: components/reminder-wrapper.tsx (root integration)
  Layout: app/layout.tsx (wraps children)
  Init: components/onboarding-form.tsx (initialization)

                          DATABASE SCHEMA
================================================================================

12 PRODUCTION TABLES

user_profile
  ├─ id, email, age, gender, height, weight
  ├─ activity_level, nutrition_goal, fitness_goal
  ├─ health_conditions[], medications[], allergies[]
  └─ onboarding_completed, completeness_score

entries
  ├─ id, user_id, raw_text, normalized_text, narrative_text
  ├─ extracted_json (20 life dimensions)
  ├─ embedding (pgvector 1536)
  └─ created_at, updated_at

daily_aggregates
  ├─ id, user_id, log_date
  ├─ calories, macros, sleep_hours, mood_score
  ├─ energy_level, stress_level, workouts_count
  └─ created_at, updated_at

audit_items
  ├─ id, user_id, entry_id
  ├─ audit_type, status (pending/approved/rejected)
  ├─ suggested_value, user_resolution
  └─ created_at, resolved_at

lab_results
  ├─ id, user_id, test_name, test_date
  ├─ results (markers), ai_analysis
  └─ created_at

day_digests
  ├─ id, user_id, digest_date
